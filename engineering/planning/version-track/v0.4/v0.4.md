# v0.4 — Ocharo sign-in

*Last updated: 2026-11-01*

**Status:** 🚧 In Progress · **Type:** Feature · **Started:** 2026-11-01 · **Completed:** —

> Ocharo's first sign-in, end to end, through its own instance: email and password with a confirmed email, and a phone
> code from Ocharo's Telegram bot, into BFF apps on the `Client` package. Order: Ocharo's P0 list (2026-11-01).
> Settings and contracts: the [sign-in configuration analysis](../../../research/sign-in-config-2026-10/sign-in-config-2026-10.md).

### Iteration 1 — Passwords and email

- [ ] Ability to set password, sign-in and lockout rules from `Identity:*` settings
- [ ] Ability to send confirmation and reset emails over SMTP, with a local mail sink
- [ ] Ability to confirm an email and reset a password through the account API
- [ ] Ability to change a password with the `None`, `Code` or `Link` confirmation
- [ ] Ability to require a password change at sign-in when the password breaks the current rules
- [ ] Fix bearer sign-in answering 500 on a cookie-only instance

### Iteration 2 — Phone by Telegram

- [ ] Ability to keep one-time codes hashed in the database and shared by instances
- [ ] Ability to link a Telegram chat to a phone through the bot's start link and shared contact
- [ ] Ability to sign in by phone with a code the bot sends
- [ ] Ability to create a person on the first phone sign-in while sign-up is on
- [ ] Ability to read the bot by webhook when hosted and by polling on a local run

### Iteration 3 — Hosted pages

- [ ] Ability to sign in, sign up and confirm an email on the hosted pages
- [ ] Ability to reset and change a password on the hosted pages
- [ ] Ability to sign in by phone and link Telegram on the hosted pages
- [ ] Ability to show an app's theme and background on the hosted pages
- [ ] Ability to read methods, theme and background per app from `GET /api/account/sign-in-options`

### Iteration 4 — Ocharo

- [ ] Ability for a BFF to sign in through the `Client` package with server-side tokens and session routes
- [ ] Ability for a BFF's API to answer 401 and 403 problems and check permissions and organizations
- [ ] Ability for an fe sdk app to follow the BFF session across tabs and end-session
- [ ] Ability to create the first organization and owner from the host CLI with preset ids
- [ ] Ability to add, list, re-role and remove members by phone from the host CLI
- [ ] Ability to always issue `name` and to issue `phone_number` under the `phone` scope
- [ ] Ability for Ocharo's apps to sign in through Ocharo's instance and return signed in

### Iteration 5 — Local runtime

- [ ] Ability to run the image on arm64
- [ ] Ability to serve HTTPS inside the container from a mounted PEM
- [ ] Ability to sign in by phone locally through a code sink and a fake Telegram channel
- [ ] Ability to check settings with `config check` before a boot

### Verification

- [ ] Run the backend tiers and the frontend lint, tests and build → all green
- [ ] Sign up locally, confirm from the mail sink, sign in through `/connect/authorize` → back at the client with a code
- [ ] Change a password under each confirmation type → refused without the code or link, changed with it
- [ ] Sign in by phone on a local run in test mode → code in the sink, signed in
- [ ] Sign in by phone with the real bot on Ocharo dev → code arrives in Telegram, signed in
- [ ] Sign in to Ocharo dev by both methods → the BFF's session route shows the person, role and permissions
