# v0.5 — Ocharo sign-in

*Last updated: 2026-11-02*

**Status:** 🚧 In Progress · **Type:** Feature · **Started:** 2026-11-01 · **Completed:** —

> Ocharo's first sign-in, end to end, through its own instance: email and password with a confirmed email, and a phone
> code from Ocharo's Telegram bot, into BFF apps on the `Client` package. Order: Ocharo's P0 list (2026-11-01).
> Settings and contracts: the [sign-in configuration analysis](../../../research/sign-in-config-2026-10/sign-in-config-2026-10.md).

### Iteration 1 — Passwords and email

- [x] Ability to set password, sign-in and lockout rules from `Identity:*` settings
- [x] Ability to send confirmation and reset emails over SMTP, with a local mail sink
- [x] Ability to confirm an email and reset a password through the account API
- [x] Ability to change a password with the `None`, `Code` or `Link` confirmation
- [x] Ability to require a password change at sign-in when the password breaks the current rules
- [x] Fix bearer sign-in answering 500 on a cookie-only instance

### Iteration 2 — Phone by Telegram

- [x] Ability to keep one-time codes hashed in the database and shared by instances
- [x] Ability to link a Telegram chat to a phone through the bot's start link and shared contact
- [x] Ability to sign in by phone with a code the bot sends
- [x] Ability to create a person on the first phone sign-in while sign-up is on
- [x] Ability to read the bot by webhook when hosted and by polling on a local run
- [x] Fix the runtime shipping a test mode, a fake bot and a message sink

### Iteration 3 — Hosted pages

- [x] Ability to sign in, sign up and confirm an email on the hosted pages
- [x] Ability to reset and change a password on the hosted pages
- [x] Ability to sign in by phone and link Telegram on the hosted pages
- [x] Ability to show an app's theme and background on the hosted pages
- [x] Ability to read methods, theme and background per app from `GET /api/account/sign-in-options`
- [x] Fix the hosted pages' look to one per instance
- [x] Ability to switch between the sign-in and account pages inside one card that animates its height
- [x] Fix sign-up and password forms checking emails and password rules only on the server
- [x] Fix the page showing a focus ring around itself after navigation

### Iteration 4 — Ocharo

- [x] Ability for a BFF to sign in through the `Client` package with server-side tokens and session routes
- [x] Ability for a BFF's API to answer 401 and 403 problems and check permissions and organizations
- [x] Ability for an fe sdk app to follow the BFF session across tabs and end-session
- [x] Ability to create the first organization and owner from the host CLI with preset ids
- [x] Ability for an owner to invite by phone, re-role and remove members from an embeddable panel (`fe-identity/admin`)
- [x] Fix account and session routes to say sign in, sign up and sign out
- [x] Ability to always issue `name` and to issue `phone_number` under the `phone` scope
- [ ] Ability for Ocharo's apps to sign in through Ocharo's instance and return signed in

### Iteration 5 — Local runtime

- [ ] Ability to run the image on arm64
- [ ] Ability to serve HTTPS inside the container from a mounted PEM
- [ ] Fix compose builds that Docker refuses for a Dockerfile outside the build context
- [ ] Ability to sign in by phone locally through a dev bot
- [x] Ability to check settings with `config check` before a boot, as the deploy's `configCheck:` step (pipelines `v0.15.0`)

### Iteration 6 — Session lifetimes

- [x] Ability to keep a fixed session for a default or an extended lifetime, chosen by "Keep me signed in"
- [x] Ability to slide a session's end with each use, set from `Identity:Sessions`
- [x] Ability for an app's refresh chain, a BFF session and a bearer refresh family to end with the sign-in session
- [x] Fix the publish failing on a pack smoke that named the removed OIDC client package
- [x] Fix the bot-off polling test failing when the service stops before its loop starts

### Iteration 7 — Sign-up modes and invitations

- [x] Ability to choose who signs up with `Identity:SignUp:Mode`, by invitation only by default
- [x] Ability for an owner or admin to make a single-use invitation link with a fixed role, bound to a phone or email
- [x] Ability to sign up by email or phone from an invitation link, joining its organization with its role
- [x] Ability for a signed-in person to join an organization from an invitation link
- [x] Ability for an owner or admin to list, re-role and remove members through `/api/organizations`
- [x] Ability to preview an invitation and sign up from it on the hosted pages

### Iteration 8 — Hardening

- [x] Fix a password guess locking out a phone or passkey person, and a lockout ending live sessions
- [x] Fix phone codes guessable across resends: one code per 30 s, 10 wrong codes per hour per number
- [x] Fix an older phone code working again after a newer one signed in
- [x] Fix sign-in routes taking unlimited requests: 30 per minute per address, Argon2 four at a time
- [x] Fix concurrent wrong passwords losing lockout counts
- [x] Fix emailed links landing on the console instead of the app the person came from
- [x] Fix `admin create --email` adopting an unconfirmed self-signed-up account
- [x] Fix `prompt=login` and `max_age` passing on an old sign-in, and `auth_time` moving with a sliding cookie
- [x] Fix any site signing a person out through a bare end-session link
- [x] Fix a phone person refused where confirmed email is required
- [x] Fix sign-up with a malformed email or long user name answering 500 after creating the account
- [x] Fix the BFF losing a rotated refresh token on a closed tab, refusing new signing keys and looping on a failed callback
- [x] Fix the email resend and "new code" messages promising what was not sent
- [x] Fix code typos spending attempts, and the kit lacking a second-factor step
- [x] Fix the role catalog living only in settings: `editor`, `viewer` and `billing` were refused unless configured

### Iteration 9 — Phone-only instance and instance admin

> The Ocharo cutover's Identity gaps (`ocharo-platform` `engineering/planning/identity-cutover.md` #8–#14).

- [x] Ability to turn password and email off with `Identity:Methods`, for a phone-only instance
- [x] Ability to give the owner an instance role with `admin create --role admin`
- [x] Ability for only instance-role holders to open the console, signed in through the hosted pages
- [x] Ability to make an invitation from the host CLI with `admin invite`, its link on the result line
- [x] Ability to deploy with the `configCheck:` step on pipelines `v0.15.0`
- [ ] Ability to sign up from an invitation page with a name, a picture and a phone verified through the bot, linking the chat (direction pending: generic Identity or an Ocharo host)
